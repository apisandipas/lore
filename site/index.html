Typed project notes, linked to code

The notes your code answers to.

Specs, decisions and module notes live as plain Markdown or Org in your repo. lore knows which of them govern each file, and hands them to you, or to your agent, before the edit is made.

From spec to ship

lore ships with agent skills for a small, strict flow. Each step is one skill, and lore next reads the notes to say which one comes next, so a session can stop anywhere and pick up tomorrow.

  1. lore-specInterview the user and write down what they want, until they accept it.
  2. lore-planTurn the spec into an effort with a task checklist, frozen against that version.
  3. lore-buildWork the first open task, reading the notes for every file before editing it.
  4. lore-shipHold the work against the spec, update the notes, mark the effort done.
~/app
lore next
next: lore-build docs/efforts/due-dates.md
  Due dates  (Effort, active)
  1 of 3 done
  next item: Show a date picker when editing a task
If the spec is edited after the plan was frozen, lore next stops pointing at lore-build and sends you back to lore-plan.

Before every edit, not after

For Claude Code, a hook runs lore context on each file the agent reads or edits and hands it the notes that govern it, once per session. In trials with real sessions, the agent followed a decision three times out of three with the hook, and none out of three without it.
