Editors

lore in Emacs

lore.el puts lore’s answers where you edit. Open any file in a lore repo and the notes that govern it are beside it, every citation is a link, and lore check problems are diagnostics at their lines.

import { sign, verify } from "./jwt";
import { store, SessionError } from "./store";

// see lore:decision/0002 -- a refresh token is good for one use.
export async function refresh(token: string) {
  const claims = verify(token);
  if (!(await store.consume(token))) {
    throw new SessionError("refresh token already used");
  }
  return issue(claims);
}

const ACCESS_TTL = 15 * 60;
const REFRESH_TTL = 30 * 24 * 60 * 60;

export async function issue(claims: Claims) {
  const refresh = sign(claims, REFRESH_TTL);
  await store.save(refresh, claims.sub);
  return { access: sign(claims, ACCESS_TTL), refresh };
}

Set up

The package is editors/emacs/lore.el, built by the flake as packages.<system>.emacs. It needs Emacs 29 or later and lore on exec-path.

init.el
(require 'lore)
(global-lore-mode 1)
(keymap-global-set "C-c l" lore-command-map)

global-lore-mode turns lore-mode on only in files under a directory with .lore/, so it costs nothing elsewhere.

Using evil with a leader key? Bind the commands under it. The letters on lore-command-map are a good guide.

The sidebar

M-x lore-sidebar-mode opens a side window listing the notes for the selected file, in lore context order: the title, which is a button that opens the note, its type and status, why it matched, and its summary. Set lore-sidebar-full to see bodies too.

It follows you. Switch windows or buffers and it refreshes after a moment of idle; save any file and it fetches again, since a saved note can change what governs anything.

Follow citations and links

M-. on a citation in code, lore:decision/0002, or on a link in a note, [[spec/auth]], [[spec/auth][the spec]] or [[file:prd.org][the PRD]], opens the note. M-? lists everything pointing at it: the code citing it and the notes linking to it.

Off a citation or link, M-. falls through to your usual backend, so it sits alongside eglot or lsp-mode without taking over.

While you write

  • Eldoc shows the title and summary of the note named at point.
  • Completion after [[ or lore: offers every note’s name, annotated with its title. Type the filename and it finds the name: bil completes to spec/billing.
  • Flymake reports lore check problems for the file at their lines: a broken link, a bad status, a citation of a superseded decision.
  • The mode line shows lore:N, the number of notes governing the file, once lore has answered. lore runs in the background and never blocks typing.

Org

In Org, lore: is a link type: [[lore:decision/0002][rotating tokens]] opens the note with C-c C-o, from any Org file inside the repo.

Limits

lore reads files from disk, so the sidebar and Flymake reflect the file as last saved. lore.el keeps no index of its own; beyond a few seconds of cached note names for completion, every answer comes from lore. Everything it uses is lore … --json, which is also the interface to build another editor’s integration on.

bun run test:emacs runs its tests in a batch Emacs against a real repo, and nix flake check runs them too.
